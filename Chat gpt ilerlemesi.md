1) Konsept & Adlandırma Proje adı: Markadan (doğru yazım bu) Amaç: E‑shopping platformu (katalog, ürün detay, kimlik, sepet/checkout) 

2) Teknik Yığın (Stack) Backend: .NET 9, ASP.NET Core Web API, Onion Architecture, Entity Framework Core (SQL Server), JWT (Bearer) ile rol bazlı yetki (Admin, User), Swagger. Frontend (güncel tercih): React (Vite) + Redux (global state) + Tailwind CSS. Not: Önceden Next.js ile BFF denendi; dev ortamında HTTPS sertifikası ve fetch davranışı kaynaklı sorunlar yaşandı (aşağıda “Sorunlar & Çözümler” bölümünde). 

3) Mimari & Katmanlar API (Presentation) → Application → Domain → Infrastructure DbContext adı: MarkadanDbContext (Infrastructure’da tanımlı) Migrations: Infrastructure katmanında tutulur; Startup/--startup-project: API. DI (AddInfrastructure): Connection string’i appsettings.json → ConnectionStrings:DefaultConnection.

(+ ileride Brand istenirse eklenebilir) Category: Id, Name ProductCategory: (ProductId, CategoryId) — Ürün ↔ Kategori = Çoka‑çok User / Role: Kullanıcı ↔ Rol = Çoka‑çok (örn. Sprint‑3 sonrası Karar: “Slug kullanılmayacak.” 

5) API Yüzeyi (Sprint bazlı) Sprint‑1 (Katalog – read‑only) GET /categories GET /products?categoryId&brandId&q&min&max&sort(price_asc|price_desc|newest)&page&pageSize GET /products/{id} Arama (q), fiyat filtreleri (min/max), sıralama ve sayfalama desteklenir. 

Sprint‑2 (Kimlik) POST /auth/register, POST /auth/login, POST /auth/refresh, POST /auth/logout, GET /auth/me JWT Bearer + role based [Authorize(Roles="Admin|User")] /admin/* gibi yönetim uçları Admin rolüyle korunur. Sprint‑3+ (Sepet/Checkout ve arka plan işler) POST /cart/add, DELETE /cart/remove, GET /cart POST /orders/checkout (Order/OrderItem’de price/title snapshot) Basit in‑process queue (Channel + BackgroundService) ile “OrderPlaced” işleri. 

6) Önemli Kararlar Slug yok. Sprint mantığı ile ilerleme. JWT ile login/refresh; role bazlı yetki. Anemic/simple domain (iş kuralları minimal; Application katmanında geliştirilir). 

7) Konfigürasyon & Çalıştırma appsettings.json (API) { "ConnectionStrings": { "DefaultConnection": "Server=YOURSERVER;Database=MarkadanDb;Trusted_Connection=True;TrustServerCertificate=True;" }, "Logging": { "LogLevel": { "Default": "Information", "Microsoft.AspNetCore": "Warning" } }, "AllowedHosts": "*" } EF Migration/Update (Infrastructure’dan, Startup=API): dotnet ef migrations add Init \ -p .\Markadan.Infrastructure\Markadan.Infrastructure.csproj \ -s .\Markadan.API\Markadan.API.csproj --context MarkadanDbContext dotnet ef database update \ -p .\Markadan.Infrastructure\Markadan.Infrastructure.csproj \ -s .\Markadan.API\Markadan.API.csproj --context MarkadanDbContext Vite (frontend) geliştirme: API CORS’ta http://localhost:5173 (veya portun) izin ver. Swagger: Dev ortamında açık; Prod’da kapalı. HTTPS yönlendirme: Dev’de zorunlu yapma (aksi halde local geliştirme zorlaşır). 

8) Geçmişte Yaşanan Sorunlar & Çözümler (Lessons Learned) Migration assembly hatası “Your target project 'IKPro.API' doesn’t match your migrations assembly…” → Çözüm: Migration’ları DbContext’in bulunduğu katmandan (Infrastructure) almak; -p Infra -s API bayraklarını doğru kullanmak. Base64 logo kaydederken String or binary data would be truncated → Çözüm: Sütun tipi/boyutu uygun seçildi (örn. nvarchar(max) / varbinary(max)); gereksiz kısıtlamalar kaldırıldı. Next.js fetch + HTTPS dev sertifikası / agent parametresi → Çözüm: https.Agent yerine ya dev’de HTTP kullan ya da TLS doğrulamayı dev için uygun şekilde kapat (örn. env değişkeni) / undici dispatcher. (Güncel stack Vite olduğundan: CORS ayarla, dev’de mümkünse API’yi HTTP çalıştır.) JWT claim key’leri (XML namespace gibi) nedeniyle decode/parsing zorluğu → Çözüm: Claims mapping’i normalize et (ör. ClaimTypes.NameIdentifier, roles); frontend’de özel parse’e ihtiyaç kalmaz. appsettings.json biçim hatası (fazladan {} bloğu) → Çözüm: JSON yapısı düzeltildi; API açılışında InvalidDataException giderildi. Connection string/Server farkı ((localdb)\MSSQLLocalDB vs makine SQL instance’ı) → Çözüm: Doğru server ve DB adıyla DefaultConnection güncellendi; migration/Swagger sorunsuz. Route param tipi uyuşmazlığı (id’nin string/route modeli) → Çözüm: Frontend istekleri /products/{id:int} formatında gönderildi; controller [HttpGet("{id:int}")] ile eşleşti. Dev’de çifte UseHttpsRedirection() → Çözüm: HTTPS yönlendirmesi yalnızca Prod’da; Dev’te kapalı.
